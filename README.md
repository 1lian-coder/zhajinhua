# 炸金花 · 异地多人网页版

一个**零依赖**的炸金花（三张牌）在线对战小游戏。发一个链接或 6 位房间号，朋友在任何地方用手机浏览器就能进桌，不用装 App、不用注册。

- **服务端发牌**：牌只在服务器，每个人只能拿到自己"看过"的牌，F12 也看不到别人的。
- **实时同步**：SSE 长连接，断线自动重连，切后台回来还是原来那手牌。
- **零依赖**：只用 Node 内置模块，`npm install` 都不用，不会有依赖漏洞、不会因为版本漂移崩。
- **积分可当惩罚**：每局结算累计净胜负分（`net`），结算页可按"1 分 = 几个惩罚"自动换算俯卧撑/深蹲。

---

## 一、3 分钟开玩（推荐：本机 + 公网隧道）

适合：几个朋友临时约一局，玩完就散。

**前提**：电脑装了 [Node.js 18+](https://nodejs.org/)（`node -v` 能出版本号即可）。

1. 双击 **`share.bat`**
   它会自动启动游戏服务 + 用 Windows **自带的 ssh** 建公网隧道（**不下载任何程序**，不会被 360 / SmartScreen 拦），大约 5~15 秒后输出：

   ```
   https://xxxx.lhr.life
   ```

   这个就是公网入口，**它会自动复制到剪贴板**，直接粘给朋友即可。

2. 你打开链接 → 输入昵称 → 输入创建口令 → **创建房间** → 把 6 位房间号（或"邀请链接"）发到群里 → 朋友点开、输昵称、进房。

3. 满 2 人即可点**开始游戏**。

### 日常操作速查

| 想做什么 | 怎么做 |
|---|---|
| 开局 / 重新开局 | 双击 `share.bat`（已在运行时直接告诉你当前地址，不会重复起隧道） |
| 查看当前地址 | 双击 `show-url.bat`（自动检测还能不能用，并复制到剪贴板） |
| 改创建口令 | 双击 `set-pin.bat`（立即生效，不用重启） |
| 全部停止 | 双击 `stop.bat` |
| 只在同一 WiFi 玩 | 双击 `start.bat`，用横幅里的 `http://192.168.x.x:8080` |

> 隧道在后台守护运行：**每 30 秒自检一次**，发现僵死自动重建并复制新地址；本地服务崩了也会自动拉起。
> 但免费隧道重连后**地址会变**，变了就把新地址重新发给朋友。想要地址永久固定，见下一节。

### 一个人也能玩：添加人机玩家

在大厅（或每局结算后）找到「人机玩家」面板，点「**+ 添加人机**」（房主操作），可加到满 6 座为止，也可以随时移除。

- 人机在**服务端**自动出牌：会看牌、跟注、加注、比牌、弃牌，按牌力和局面决策
- 你**关掉浏览器它照打**，断线重连回来牌局还在
- 真人朋友随时照常加入，人机不占真人的体验（同一套规则和校验）
- 筹码不足自动补到初始值（跟真人一致），积分照常计入惩罚换算

### 为什么不用局域网？

你们不在同一个地方，`192.168.x.x` 这种局域网地址朋友访问不到，所以必须穿透到公网。

## 二、三种长期方案对比

| 方案 | 成本 | 地址稳定性 | 适合 |
|---|---|---|---|
| **A. 本机 + SSH 隧道**（`share.bat`，零下载） | 免费 | 每次断开重连会变 | 临时约局、玩一两晚 |
| **B. 免费云平台**（Render / Zeabur / Railway） | 免费额度 | 固定域名，但免费实例会休眠，首次打开要等 30~60 秒 | 想随时能开，不介意冷启动 |
| **C. 自己的服务器**（云主机 / 树莓派 / NAS） | 每月十几块 | 固定域名 + 永不掉线 | 长期固定圈子玩，最省心 |

### B. 免费云平台（以 Render 为例）

1. 把 `D:\VSCode\zhajinhua` 整个目录推到 GitHub 私有仓库（`data/` 下的口令和房间数据会被 `.gitignore` 忽略）。
2. 打开 [render.com](https://render.com) 用 GitHub 账号注册/登录（免费）。
3. 直接点一键部署（会自动读取仓库根目录的 `render.yaml`）：
   `https://render.com/deploy?repo=https://github.com/<你的用户名>/zhajinhua`
4. 按提示填一次环境变量 `CREATE_PIN`（创建房间口令），点 Apply。
5. 等 2~3 分钟构建完成，拿到 `https://xxx.onrender.com`，发这个链接就行。

> 手动方式：New → Web Service → 连仓库 → Runtime `Node`、Start Command `node server.js`，
> 再到 Environment 里加 `CREATE_PIN=你的口令`（可选）。
>
> 口令通过环境变量 `CREATE_PIN` 下发，**不要**把口令写进 `data/settings.json` 一起提交。

注意：Render 免费实例 15 分钟无流量会休眠，**正在打牌时因为有 SSE 长连接不会休眠**，但开局前第一次打开可能要等半分钟。云上磁盘是临时的，`data/rooms.json` 不会跨重启保留，房间在内存里，重启后需要重新开房（积分本就是按会话算的）。

### C. 自己的服务器（Linux）

```bash
# 上传项目后
cd /opt/zhajinhua
node -v            # 需要 >= 18
PORT=8080 node server.js          # 先手动跑通

# 用 pm2 常驻 + 开机自启
npm i -g pm2
pm2 start server.js --name zhajinhua
pm2 save && pm2 startup
```

然后在服务器安全组放行端口，或用 Nginx 反代（**必须关掉缓冲**，否则 SSE 会延迟）：

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Connection '';
    proxy_buffering off;          # SSE 关键
    proxy_read_timeout 3600s;
}
```

也可以直接用 Docker：

```bash
docker build -t zhajinhua -f deploy/Dockerfile .
docker run -d -p 8080:8080 -v $(pwd)/data:/app/data --name zhajinhua zhajinhua
```

## 三、玩法与规则

### 房间密码（可选）：只让拿到密码的朋友进房

房主在大厅的「房间密码」区设置一个 **4~8 位数字密码**：

- 设置后，朋友必须输入「房号 + 密码」才能进；不设则凭房号即可
- 随时可改或清空（留空保存 = 取消密码）
- 密码明文**永远不下发给任何人**（连房主自己刷新后也看不到，只显示"已设置"）
- 连输错 20 次会锁定 10 分钟，防穷举
- 注意区分：**创建口令**限制"谁能开房"，**房间密码**限制"谁能进这个房"

### 自动连开下一局

房主在设置里打开「自动开下一局」并设置等待秒数（默认 8 秒）：

- 每局结算后倒计时，到点自动发牌开下一局，不用每次手动点
- 结算页会显示"N 秒后自动开下一局"，任何人可点「先别开」取消本局
- 手动点「下一局」会立即开始并清空倒计时
- 人不够/筹码不足导致开不了局时，会自动暂停并写进日志

### 创建口令（可选）：只允许被授权的人开房

默认任何打开链接的人都能创建房间（各房间互相独立，互不影响）。如果你希望**只有你授权的人能开房**：

1. 双击 **`set-pin.bat`**，输入一个 3~8 位数字口令（直接回车可随时取消）。
2. 之后创建房间必须填这个口令；**朋友凭 6 位房号加入不受影响**。
3. 改动立即生效，服务不用重启。口令存在 `data/settings.json`，别提交到 GitHub。

前端行为：首页「创建房间」里会自动多出一个口令输入框；输错会提示。连续输错 15 次会锁定 10 分钟（防猜口令）。

界面上的操作：

| 操作 | 说明 |
|---|---|
| **看牌** | 偷看自己的三张牌。看牌后你变成"明牌"，**下注额 ×看牌倍数**（默认 2 倍）。看牌前是真的看不到——服务端不会把牌发给客户端。 |
| **跟注** | 按当前单注下注（闷牌跟注 = 单注；明牌 = 单注 × 倍数） |
| **加注** | 把单注提高，受"单注封顶"限制 |
| **孤注一掷** | 筹码不够跟注时出现：把剩下的全部押上，留在牌局里直到开牌。结算按**侧池规则**——你只能赢到对手投入被你匹配到的部分，公平不吃亏。其余人都全下/弃牌时自动开牌。 |
| **比牌** | 付一次跟注的钱，指定一个人和你比大小，输的人当场出局。**平局时主动比牌的人输**。 |
| **弃牌** | 退出本局，已下的注不退 |

**牌型大小**（从大到小）：

```
豹子（三条） > 顺金（同花顺） > 金花（同花） > 顺子 > 对子 > 单张
```

- **A23 算最小的顺子**，234 比它大；QKA 是最大的顺子。
- **235 不同花**默认算普通单张。如果你们那儿的规矩是"235 通杀豹子"，房主可以在设置里开启 `235通杀`。

**一局怎么结束**：

1. 只剩一个人没弃牌 → 他赢走整池；
2. 底池达到「总注封顶」→ 全员开牌，最大的一家（或几家平分）赢；
3. 比牌把人比到只剩一人 → 立即结算。

**房主可调参数**（大厅界面里改）：

| 参数 | 默认 | 含义 |
|---|---|---|
| 底注 `ante` | 10 | 每局开始每人必下的注 |
| 初始筹码 `initialChips` | 1000 | 每人开局筹码 |
| 初始单注 `baseStake` | 10 | 闷牌跟注的基准金额 |
| 单注封顶 `maxStake` | 100 | 一次最多能加到这个数 |
| 总注封顶 `maxPot` | 3000 | 底池到这么多就强制开牌，防止无休止跟注 |
| 看牌倍数 `seeMultiplier` | 2 | 看牌后下注翻几倍 |
| 235 通杀 `special235` | 关 | 235 不同花是否通杀豹子 |
| 思考时间 `turnSeconds` | 45 | 超时自动弃牌，0 = 不限时 |

## 四、积分与惩罚

- 每个人有一个 **净胜负分 `net`**：赢的减掉下的，全程累计，和为 0。
- 筹码可以补（牌局开始筹码不够时自动补到初始值），但**补筹码不影响 `net`**，所以分数永远真实。
- 结算页有个「惩罚换算」小面板：填「1 分 = 几个惩罚」，立刻算出谁该做多少个俯卧撑/深蹲。

  > 例：`net = +120` 且 1 分 = 1 个俯卧撑 → 赢家可以让输家做 120 个，或者大家分摊。想温和点就填 0.1。

## 七、常见问题

**双击 share.bat 时弹「Windows 安全中心 / 360 已阻止此程序」？**
这是安全软件在拦**公网穿透工具**，不是拦游戏本身。当前 `share.bat` 用的是系统自带的 `ssh`，**不下载任何 exe**，正常不会再被拦。
如果仍然被拦，通常是拦 `ssh.exe` 的外连：在 360 的「防护日志 / 恢复区」里把 `C:\Windows\System32\OpenSSH\ssh.exe` 加信任，或者把整个 `D:\VSCode\zhajinhua` 目录加进信任区。
旧方案 `tools\share-tunnel.ps1` 会下载 `cloudflared.exe`，这个 exe 没签名，很容易被 360 拦——所以默认已改用 ssh 方案。

**朋友打开链接一直转圈/进不去？**
先确认你电脑没睡眠、`share.bat` 窗口还开着。隧道断开后地址就失效了，重新跑一次会拿到新地址。

**为什么换了个链接就要重新输昵称/进不了原来的房间？**
昵称和座位身份存在浏览器里，是**跟着网址走**的。免费隧道每次重连都会换一个新网址，相当于换了个"网站"，所以昵称要重输。
两个办法：
- 临时：玩的时候用当天发的链接，中途别混用旧链接；
- 根治：部署到云端拿到固定网址（见第二节方案 B/C），昵称和身份就永远记住了。

**页面点什么都没反应 / 显示"页面没有加载完整"？**
这几乎总是因为**公网链接已经过期**（免费隧道会失效）。新版 `share.bat` 每 30 秒自动体检、失效自动重建并复制新地址，把新地址重新发给朋友即可。

**为什么我看不到自己的牌？**
没点「看牌」。这是故意的——闷牌就是真闷，服务端不把牌下发给前端，防止有人开控制台偷看。

**有人掉线了怎么办？**
不会卡场：轮到他时会给一段宽限（限时局取思考时间的一半，不限时局 30 秒），还没回来就由**系统托管自动出牌**（不会代你看牌，保持你的闷/看状态）；他重新打开链接会凭本地保存的身份自动回到原座位，筹码和分数都在。

**能不能加语音？**
可以自己接腾讯会议/微信语音，边打边聊。游戏内也有**快捷聊天**（💬 按钮，8 个常用短语 + 自定义输入，30 字内），说话会显示在头像上的气泡。

**服务端会不会崩溃？**
所有入口都有 try/catch，`uncaughtException` 也只记录不退出；房间状态约每 10 秒落盘到 `data/rooms.json`，重启后房间、玩家身份和积分都还在（进行中的那一局会作废并原额退还下注）。

### 观战怎么用

打开游戏首页往下滑，会看到 **「实时牌局」** 面板，每 3 秒自动刷新：

```
837261 | 4/8人 · 进行中 · 第3局 · 底池120
                                  [观战]
```

点「观战」就进入牌桌旁观。观战者：

- **看不到别人的暗牌**——和真人一样，只有开牌（showdown）后牌面才会公开，所以不能用来作弊
- 不能出牌、不能抢庄、不能改设置（所有操作按钮都会隐藏）
- 可以看聊天、看下注筹码、看结算结果，自己也能发言
- 房间有密码时需要先输密码才能观战
- 观战人数上限 20 人，不影响玩家座位（15 个座位照常给玩家）

## 八、安全说明（部署到公网前看这一节）

### 部署到云端，比"本机开隧道"更安全

现在这种玩法是**把公网流量引到你自己的电脑**：隧道服务把 `https://xxx.lhr.life` 的请求转发到本机 8080。
部署到云端后，游戏跑在云厂商的隔离容器里——**你电脑不再对外提供任何服务**，攻击面从"你的整台电脑"缩小成"一个只跑这 40KB 程序的容器"。
另外云平台免费自带 HTTPS 证书和基础 DDoS 防护，而你本地跑隧道时，TLS 是隧道商的。

### 已经内置的防护

| 层面 | 措施 |
|---|---|
| 身份 | 每个玩家一个随机 32 位 token，所有操作都要校验；没有 token 动不了任何一局 |
| 建房授权 | 可选创建口令（`set-pin.bat`），输错 15 次锁 10 分钟；加入房间不受影响 |
| 刷接口 | 建房限频（5 次/3 秒）+ 房间总数上限（默认 50）+ 全服人数上限（默认 150）；加入限频 30 次/3 秒 |
| 刷连接 | 同一玩家最多 3 条 SSE 长连接，全服最多 300 条；超出直接 503 |
| 偷看牌 | 牌只在服务端，没点"看牌"前前端根本拿不到自己的牌，更拿不到别人的；弃牌的人也不亮牌 |
| XSS | 昵称渲染全部走 `esc()` 转义或 `textContent`；服务端另有一层字符清洗（去控制字符、限长 12） |
| 注入/路径穿越 | 没有数据库、没有 SQL；静态文件服务做了路径规范化，越界访问返回 403 |
| 依赖漏洞 | **零第三方依赖**，不存在 npm 供应链风险 |
| 稳定性 | 请求体限 64KB、全部入口 try/catch、`uncaughtException` 不退出、进程级兜底 |

### 残余风险（说实话）

1. **公网地址可能被扫描到**。有口令的话，陌生人建不了房；但加入只需要 6 位房号，理论上可以被穷举撞进某个房间。对朋友局来说影响有限（顶多被人围观），介意的话可以再给房间加密码。
2. **免费云实例会休眠**，第一个访问的人要等 30~60 秒唤醒。
3. **别把 `data/settings.json` 提交到 GitHub**（里面有你的创建口令），`.gitignore` 已经排除 `data/rooms.json`，提交前顺手确认一下 settings.json 也不在版本里。
4. **这个程序没有账号体系**，不要在里面填真实手机号、身份证之类的信息。

### 语音统一为荷官音（修复新旧音色混杂）

- 原因：Edge 荷官音偶发失败时会回退 espeak 机器人音，且回退结果被缓存；浏览器也缓存了旧音频
- 修复：
  - 荷官音**失败自动重试 2 次**，仍失败才临时回退（回退缓存只保留 1 分钟，之后重试荷官音）
  - 回退音频响应标记 `no-store`，浏览器不再缓存旧音
  - 所有合成**串行排队**，避免多个 edge-tts 并发被限流超时
  - TTS 接口带语音版本号（`/api/tts?...&v=e2`），`/api/health` 返回 `ttsVer`；换音色只需改版本号，客户端自动换新 URL

- 合成顺序：**Piper（约 0.3~0.5 秒）→ Edge 云端（备选）→ espeak（兜底）**
- 常驻 piper 进程（模型只加载一次），启动后自动预热「语音播报已开启」
- TTS 版本号升级为 `p1`，客户端自动换新音频地址，不再混入旧音
- 轮到的玩家提前合成「XX 押注 X」，命中缓存后几乎即时

### 轮次机制：局数可改 + 打完一轮可继续（不再强制新开房间）

**局数设置**
- 房主可在**大厅**任意修改局数（`每轮局数`，0=不限）；本轮打完后也能改
- 本轮结束的结算界面新增「**修改设置（局数等）**」按钮，房主点一下回大厅改，改完点开始就是新一轮

**打完一轮怎么办**
- 结算界面按钮：「**开始第 N 轮**」「修改设置（房主）」「离开」
- **没人点下一轮 → 停在结算界面**，可以继续观战或退出，房间不会自己开新局
- **有人点下一轮 → 排定 30 秒集合倒计时**，期间其他人也能点加入
- 30 秒内没点的人 → **本轮先观战**（之后随时可点「参与」回来）
- 已退出房间的人、人机、观战者**不计入**等待名单
- 倒计时结束自动进入新一轮，**沿用上一轮的房主设置**（房主不在也照常进行）
- 新一轮回到大厅，房主在的话可以继续调整设置，其他人点「开始」即可开局

**接口**：`POST /api/nextRound`

### 加入房间需房主审批（防止乱拉人）

- 新设置项「**新人进房需房主同意**」（默认开启）
- 流程：任何人点「加入」→ 只发出**加入申请**，房主同意后才真正进房间
- 申请人界面：显示「⏳ 已向房主发出加入申请」，自动轮询，房主同意后**自动进入房间**；被拒绝会有提示
- 房主：顶栏新增「**申请 N**」按钮（有申请时高亮闪光），点开可**同意 / 拒绝**每一条申请
- 房间密码仍然有效：密码校验通过才会发出申请（双重门槛）
- 房间设置为「不需要审批」时恢复成直接加入
- 观战仍用创建口令 + 房间密码门槛，不需要房主审批
- 申请 30 分钟无人处理自动失效，已处理的申请 10 分钟后清理
- 新接口：`/api/requestJoin`、`/api/joinStatus`、`/api/approveJoin`、`/api/rejectJoin`

### 准备机制：全员就绪才能开局

- **任何人进房后默认未准备**；人机自动就绪
- **非房主**：底部按钮显示「准备」，点一下变「✅ 已准备 · 等待房主开始」
- **房主**：底部按钮显示「等待准备（X/Y）」，**必须所有人准备好**才会变成可点的「开始游戏」
- 房主硬点开始会被拒绝，并提示「还有 N 人没准备：某某、某某」
- 大厅面板新增「准备状态」区块：每人一个标签（⏳待准备 / ✅已准备 / 人机就绪 / 观战）
- 观战者不需要准备；观战状态下不能点准备
- 同一轮内后续几局不需要重新准备（开局后准备状态自动清零）
- 一轮打完点「开始第 N 轮」的人视为已准备，进入新一轮后即可开局
- 新接口：`POST /api/ready`
